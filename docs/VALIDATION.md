# 验证记录

更新：2026-11-14（Australia/Sydney）。

## v0.5.0 双阶段与精简安装版

- 发布前完整自动检查：47 项 Python 测试、3 项 Node 播放器测试通过；Ruff、格式和 JavaScript 语法检查通过。

- Windows RTX 5080，PyTorch 2.7.1+cu128；RTX 5090 未实机测试，运行构建包含 `sm_120`。
- 新版独立窗口实际完成：环境检查 → 模型来源下载与校验 → 中文路径 MP3 导入 → 整曲分离 → 选择候选 2 写入目标 → 整曲导出 → 播放/暂停 → 退出。
- 277.333 秒歌曲实际总处理 51.851 秒（含加载与模型校验），去伴奏阶段 28.810 秒。
  导出为 44.1 kHz、12,230,400 个样本；目标与候选 2 逐样本相同，目标加残差与单声道原音最大误差 `5.96e-8`。
- 与 M1 完整候选回采样对比，余弦相似度为 0.999976 / 0.999959；45 秒预览为 0.999970 / 0.999963。
  CPU/GPU 累加和采样率往返带来微小数值差异。这是回归一致性检查，不是分离质量评分。
- 新安装器能识别无 Python 和旧环境缺少的 19 项新增依赖；通过安装器补齐后依赖、Qt、音频库与 CUDA FFT/cuDNN 检查通过。
- 本次在既有隔离环境上验证依赖升级，未重新下载整套 CUDA 环境；原有首次 Python/CUDA 安装流程见 v0.4 验证。
- 安装器中文按钮文字可见，无裁切；主程序是独立 Qt 窗口，无需外部浏览器。
- 两个新来源归档实际从固定作者地址下载并校验；约 913 MB 的 RoFormer 权重复用此前已下载且哈希一致的文件。
- 自动回归覆盖：必须试听后显式选择才可导出、候选二整轨/局部写入、选区外不变、撤销、新分离保留原目标、异常输出不覆盖原候选、模型来源篡改修复和重叠排列匹配。

一首歌的用户试听反馈为“进步非常明显”，详细范围见 [M1 节点](MILESTONE_M1.md)。
没有逐段身份真值，没有全面确认所有和声归属；不把单曲反馈或数值一致性当成跨歌曲质量保证。

## v0.4.0 后的参考采样率修正（随 v0.5.0 发布）

- 当前源码将默认参考采样率从 16 kHz 改为 44.1 kHz；引擎、API、CLI、界面及模型清单一致。
- 43 项 Python 测试通过（含真实权重测试），覆盖 API 默认值及显式 16 kHz 对照的传递；3 项 Node 测试及 Ruff 检查通过。
- 公开独立人声的 6 次目标提取诊断中，新设置有 5 次改善，仍有一次明显提错人声。
  逐项分数和局限见 [模型说明](MODEL_NOTES.md)，不能作为完整数据集或商业歌曲质量保证。
- 用户歌曲按相同 00:20–00:23 参考重新处理，实际使用 RTX 5080 CUDA；
  输出仍为 44.1 kHz、12,230,400 个样本，目标加残差误差小于 `6e-8`。
  该参考尚未确认是单人独唱，重跑音频尚未通过试听验收。
- 该修正现保留在 v0.5.0 的旧版对照模式中；双阶段管线作为新的默认模式。
